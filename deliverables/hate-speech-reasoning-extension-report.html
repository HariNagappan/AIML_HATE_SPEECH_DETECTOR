01Outcome

The reasoning pipeline is complete: prediction → target → reason → evidence (with character offsets) → deterministic reason explanation → structured response → UI.

  • Evidence offsets — every span now carries start/end character offsets into the original comment (end-exclusive) plus inclusive token ranges; live-verified to slice-match the input exactly.
  • Reason explanation engine — app/reasoning/reason_explainer.py: fixed templates for all 8 reason categories → {summary, details, grounded_in}. Deterministic, grounded, configurable. No LLM anywhere.
  • Extended contract — /api/v1/predict returns reason_explanation + evidence_available; /explain updated as well.
  • Frontend — a "Why this classification?" section with numbered, clickable evidence cross-references; evidence numbering on highlights and in the list; About page updated; vitest test suite added.
Honesty constraints hold: no explanation without a trained reason head; no intent claims; no causal context claims; everything renders from structured fields only.

05Caveats & activation

  • "Why this classification?" is availability-gated. It renders only when the served model has a trained reason head. The current checkpoints have no reason-annotated training data (no fabricated labels), so the section stays hidden for now.
  • Activation path is wired, tooled and tested — train with use_reason: true and real reason annotations (the backend ships scripts/import_reason_annotations.py + configs/cc_reason.yaml for this); the explanation then appears automatically (the unit/integration test proves the full path end-to-end).
  • Offsets are end-exclusive; token ranges inclusive. Both documented in schemas and README.
  • The explanation describes the model's structured output — not the author's intent, and not proven causation ("context was included", never "context caused").
