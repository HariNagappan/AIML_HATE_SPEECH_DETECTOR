03Architecture at a glance

current comment ─┐
                 ├─> SHARED BERT ─> E_c, E_p
previous context ┘                  │
      D = |E_c − E_p|                │
      M = E_c ⊙ E_p                  ▼
      E_int = [E_c;E_p;D;M] → 3072 → Linear→GELU→Dropout → final repr
                                                            │
              ┌──────────────┬──────────────┬───────────────┴─────────┐
              ▼              ▼              ▼                         ▼
          HATE HEAD      TARGET HEAD    REASON HEAD        EVIDENCE (token-level)
        (hate/offensive  (9 canonical   (8 categories,     + post-hoc attribution:
         /normal)         categories)    only when          Integrated Gradients →
                                         annotated)         input-grounded spans

Design guarantees

  • One encoder, weight-shared for comment & context.
  • No context → zero-vector fallback, context_used=false.
  • Contrastive learning is training-only; never used at inference.
  • Reason head never trained on fabricated labels.
  • Evidence = actual input spans, not generated text.

04Datasets — verified against the real corpora

Both datasets were downloaded and fully parsed by the adapters. They are never merged at the raw level — each has its own adapter and its own label mapping into the shared internal format.

Counter Context (silver)counter_context.py1,675419—same schema; kept separate from gold

Findings from live schema inspection

  • HateXplain layout: the corpus file is an id → record mapping (20,148 records), and records carry post_id — the adapter was aligned to the real format and re-verified on all records.
  • Rationale coverage: token-level rationales exist for 9,132 / 15,383 training records (≈59%). Evidence training and evaluation use exactly this annotated subset; the rest carry None (never fabricated).
  • Counter Context naming quirk: the field "target" holds the current comment and "context" the preceding comment — documented in the adapter; the unified format renames them to current_text/context_text.
  • Target vocabulary: real community strings (e.g. Heterosexual, Buddhism, Minority, Indian) were mapped to the canonical categories — the gold splits now contain zero unmapped targets.
  • Label order (Counter Context): ids "0/1/2" map by default to hate_speech / counter_speech / neither; kept configurable — see §07.

06How to run

Everything runs from inside backend/. The datasets are already downloaded and preprocessed on this machine, so training can start immediately.

# 1) install dependencies (Python 3.11+)
pip install -r requirements.txt

# 2) datasets (already done here; scripts are idempotent)
python scripts\download_data.py --dataset all
python scripts\preprocess.py

# 3) train
python scripts\train.py --config baseline                    # BERT only
python scripts\train.py --config context --dataset counter_context
python scripts\train.py --config full                        # multi-task

# 4) evaluate + explain
python scripts\evaluate.py --checkpoint checkpoints\full\best.pt
python scripts\explain.py --text "They should all be kicked out." --context "Those immigrants are ruining everything."

# 5) serve (point MODEL_CHECKPOINT at a trained checkpoint)
$env:MODEL_CHECKPOINT="checkpoints\full\best.pt"
uvicorn app.main:app --reload

# 6) tests
python -m pytest -q

Example API call:

POST /api/v1/predict
{"text": "They should all be kicked out.", "context": "Those immigrants are ruining everything."}

→ {"prediction": {"label": "hate", "confidence": 0.94, ...},
   "target": {"label": "nationality", ...}, "reason": null,
   "reason_available": false, "evidence": [{"text": "kicked out", "score": 0.82}],
   "context_used": true}

07Caveats & next steps

  • [verify] Counter Context label order. The default mapping "0→hate_speech, 1→counter_speech, 2→neither" could not be independently confirmed from the paper during this build (search services were degraded). Verify against the NAACL 2022 paper and adjust configs/base.yaml → datasets.counter_context.label_map if needed.
  • Evidence supervision uses ~59% of HateXplain. Records without rationale annotations are excluded from evidence loss/eval automatically — no fake targets.
  • Reason head is untrained by default. It requires a reason-annotated dataset or a custom annotation file (wired in configs); until then the API reports reason_available: false.
  • Train before serving meaningful output. Without MODEL_CHECKPOINT the backend runs but reports all heads as unavailable (deliberate honesty rule).
  • CPU training is slow — DEVICE=auto enables CUDA automatically when available.

Suggested next steps

  1. Verify the Counter Context label order; adjust the YAML if needed.
  2. Train baseline → context → full and run the ablations (experiments/).
  3. Plug in a reason-annotated dataset when available to supervise the reason head.
  4. Build the frontend chat UI against POST /api/v1/predict (already designed for it).
